# 3.5 — Compare and contrast network access and management methods

## VPN types

### Site-to-site vs. client-to-site

| | **Site-to-site** | **Client-to-site** |
|---|---|---|
| Connects | **Network to network** | **Device to network** |
| Tunnel endpoints | **Gateway to gateway** — routers or firewalls | **Host to gateway** |
| Software on the host | **None** | **VPN client** |
| User awareness | **Transparent** — users never know it exists | A deliberate connection |
| Duration | Normally always on | On demand |

**Site-to-site extends the network; client-to-site extends membership to one device.** In a site-to-site tunnel a workstation reaches a remote server as though both were local, with no client, login, or awareness that a tunnel exists. Typically implemented with IPsec.

**⚠️ A reverse proxy tunnel is not a VPN.** An outbound-initiated tunnel that publishes a single service inbound — such as a Cloudflare Tunnel — is often confused with one. A VPN joins a network bidirectionally; a reverse proxy tunnel exposes one service outward through a connection the host initiated.

### Clientless
Access through a **web browser over TLS**, with no client software installed. The gateway presents a **portal** brokering access to specific applications.

**⚠️ It is not a network connection.** The user receives no address on the network, only proxied access to whatever the portal can broker — typically web applications, sometimes RDP or SSH through browser-based clients. **The trade is reach for capability:** it works from any browser on any device, which suits contractors, BYOD, and unmanaged machines, but anything the portal cannot proxy is unreachable.

### Split tunnel vs. full tunnel

| | **Full tunnel** | **Split tunnel** |
|---|---|---|
| Traffic through the VPN | **All of it**, including internet-bound | **Corporate destinations only** |
| Internet traffic inspected | **Yes** | **No** |
| VPN bandwidth consumed | **High** — everything hairpins through the gateway | Low |
| Internet latency | Higher | **Direct** |
| A compromised host's C2 traffic | **Visible** | **Invisible** |

**The trade-off is security against capacity**, and it has been forced in practice: full tunnel could not carry entire remote workforces, since cloud application traffic alone would saturate a concentrator, so many organisations adopted split tunnel from necessity rather than preference.

**⚠️ Split tunnel blinds network monitoring for remote users.** A compromised laptop reaches its command-and-control infrastructure directly, never crossing the inspection point — flow data, IDS, and DNS logging all miss it. **This is why endpoint agents matter more in a split-tunnel environment:** one of the independent vantage points described in objective 3.2 has been removed, leaving only the other.

A secondary concern is **bridging** — a client attached simultaneously to the VPN and a hostile local network is in principle a path between them.

## Connection methods

| Method | Transport | Encrypted | Scriptable | Requires the network |
|---|---|---|---|---|
| **SSH** | TCP 22 | Yes | Yes | Yes |
| **GUI** | HTTPS, or a vendor thick client | Yes | Poorly | Yes |
| **API** | HTTPS / gRPC | Yes | **Best** | Yes |
| **Console** | **Serial cable** | — | Poorly | **No** |

**⚠️ The console's value is that it does not use the network.** A serial connection reaches the device's UART directly — no IP, no routing, no firewall, no VLAN — so it works regardless of whether anything else does. That makes it the **recovery path** when a configuration change severs management, the **initial configuration path** for a device with no address, and the only method surviving a total network failure.

**It is also why physical security is access control:** anyone able to reach the console port receives a login prompt regardless of every network control in place.

**SSH replaced Telnet**, which carries credentials in cleartext on TCP 23 and should not be enabled.

**GUI and CLI are a genuine trade-off rather than a preference.** A GUI is better for **discovering state**, since everything is visible without knowing what to ask; a CLI is better for **making changes**, being faster, reproducible, and pasteable into documentation. A GUI also presents a **larger attack surface**, being a web application with vulnerabilities of its own.

## Jump box / host
**A single hardened entry point into a protected segment.** Administrators connect to it and reach their targets from there; nothing else in the segment is directly reachable from outside.

**It provides:** a **smaller attack surface**, since one host is exposed rather than many; **concentrated monitoring**, since all administrative access passes one point and can be logged or session-recorded once; and **a chokepoint for policy**, where MFA and authorisation are enforced.

**⚠️ Concentrating access also concentrates risk.** A compromised jump box is a launchpad to everything behind it, so it must be the most hardened host in the estate — minimal software, **no general internet access**, MFA, session recording, and prompt patching. **A neglected jump box is worse than none**, being a single trusted and unmonitored path to everything.

## In-band vs. out-of-band management

| | Management travels | When the network fails |
|---|---|---|
| **In-band** | **Over the production network** | **Management is lost with it** |
| **Out-of-band** | **A separate physical path** | **Still reachable** |

**Out-of-band paths** include console servers, dedicated management interfaces, **IPMI / iDRAC / iLO** baseboard controllers with their own network ports, cellular modems, and physically separate management networks.

**⚠️ In-band management is a dependency loop — the network must work in order to repair the network.** That is tolerable until the day it is not, and that day is precisely when it was needed.

**⚠️ A management VLAN is not out-of-band.** A dedicated VLAN improves isolation but rides the same switch, cabling, and silicon as production traffic, so a bridge or configuration failure removes it along with everything else. **Segmentation is not separation of infrastructure** — a separate *path* is out-of-band, a separate *VLAN* is not.
