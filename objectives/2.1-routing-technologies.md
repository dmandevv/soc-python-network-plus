# 2.1 — Explain characteristics of routing technologies

### Static routing
Routes configured **manually** by an administrator and held until manually changed. The router performs no discovery and exchanges nothing with neighbours.

**Advantages:**
- **No protocol overhead** — no CPU, memory, or bandwidth spent on updates
- **Predictable** — the path is exactly what was configured
- **Secure** — nothing is advertised, so nothing can be intercepted or spoofed by a rogue neighbour
- **Administrative distance of 1**, so a static route is preferred over anything a dynamic protocol learns

**Disadvantages:**
- **No automatic failover.** If the configured next hop goes down, the route stays in the table and traffic is black-holed until someone intervenes.
- **Does not scale** — every route on every router, by hand
- **Error-prone** at scale, and a mistake persists until noticed

**Where it fits:** small networks, stub networks with only one way out, and **default routes**. A default route (`0.0.0.0/0`) is the most common static route of all — "anything I don't have a specific route for, send here" — which is what every home router and most branch offices use.

**The failover caveat matters:** static routing's lack of reaction to failure is its defining weakness. Mitigations exist (floating static routes with a higher administrative distance as backup, or IP SLA tracking that withdraws a route when a target becomes unreachable), but plain static routing simply does not notice a broken path.

### Dynamic routing
Routers **discover routes by exchanging information with neighbours** and recalculate automatically when the topology changes. The administrator configures the protocol, not the individual routes.

**What it provides:** automatic failover when a link fails, adaptation as networks are added or removed, and scalability — a new subnet is advertised once and propagates itself.

**Its costs:** CPU, memory, and bandwidth consumed by protocol traffic; **convergence time** during which the network is inconsistent; and an attack surface, since a rogue device that speaks the protocol can inject false routes unless authentication is configured.

**The three classifications:**

| Type | How it works | Examples |
|---|---|---|
| **Distance-vector** | Shares its whole routing table with direct neighbours periodically — "routing by rumour" | RIP |
| **Link-state** | Every router floods link status, builds a full topology map, runs Dijkstra's SPF independently | **OSPF**, IS-IS |
| **Path-vector** | Advertises the full AS path to a destination, used between autonomous systems | **BGP** |

**EIGRP** is Cisco's **hybrid / advanced distance-vector** protocol — it uses neighbour relationships and triggered updates like a link-state protocol, but its algorithm is distance-vector at heart.

**Interior vs. exterior:** **IGPs** (OSPF, EIGRP, RIP, IS-IS) run *within* one autonomous system. **BGP** is the only **EGP**, running *between* autonomous systems — it is what routes the internet.

**Convergence** is the key metric: how long after a change before every router agrees on the topology again. During convergence, routing loops and black holes are possible, which is what split horizon, route poisoning, and hold-down timers exist to limit.

### Border Gateway Protocol (BGP)
The **path-vector** protocol that routes between autonomous systems — the only **exterior gateway protocol** in use, and what makes the internet a single routable network.

**An autonomous system (AS)** is a network under one administrative authority, identified by an **ASN**. Every ISP, large enterprise, and cloud provider has one. BGP is how they exchange reachability.

**What makes it path-vector:** a BGP advertisement carries the **full list of autonomous systems** a route passes through. That AS path serves two purposes — it is the primary distance metric (fewer AS hops is generally preferred), and it provides **loop prevention**: a router that sees its own ASN already in a path discards the advertisement.

**Its defining characteristic is policy, not performance.** Unlike IGPs, which optimise for a metric like cost or hop count, BGP decisions are driven by **business relationships** — peering agreements, transit costs, and contractual preferences. Internet traffic routinely takes geographically indirect paths because of them.

**Other properties:** runs over **TCP 179** (unusual — most routing protocols use their own transport), converges slowly by design to avoid churn in a table of nearly a million routes, and is deliberately conservative about accepting change.

**Security:** BGP has historically trusted advertisements implicitly, which enables **BGP hijacking** — announcing address space you do not own so traffic is diverted to you. Real incidents have redirected traffic for banks and cryptocurrency services. **RPKI** exists to cryptographically validate that an AS is authorised to announce a prefix.

**Exam scope:** know that BGP is path-vector, exterior, AS-based, and runs the internet. Its best-path selection algorithm is beyond N10-009.

### Enhanced Interior Gateway Routing Protocol (EIGRP)
Cisco's **hybrid / advanced distance-vector** interior gateway protocol. Distance-vector at its core, but with behaviours borrowed from link-state designs.

**What makes it hybrid:**
- **Neighbour relationships** established and maintained with hello packets, rather than blind periodic broadcasts
- **Triggered updates only** — it advertises when something changes, not on a timer
- **Partial updates** — only the changed routes are sent, not the entire table
- Maintains a **topology table** of all known routes, not just the best ones

**The DUAL algorithm** is its distinguishing feature. EIGRP precomputes a **successor** (the best path) and a **feasible successor** (a guaranteed loop-free backup). If the successor fails, the backup is installed **immediately** — no recalculation, no convergence delay. That is why EIGRP converges faster than most alternatives.

**Its metric is composite**, based primarily on **bandwidth and delay** (load and reliability are available but disabled by default) — more nuanced than RIP's hop count, since it distinguishes a fast link from a slow one.

**Administrative distance:** **90** internal, **170** external — internal EIGRP is trusted above OSPF's 110.

**Its limitation is vendor lock-in.** EIGRP was Cisco-proprietary for most of its life and, although partially opened as an informational RFC in 2013, remains effectively Cisco-only in practice. **OSPF is the open-standard choice** for multi-vendor environments — which is why OSPF dominates despite EIGRP's faster convergence.

### Open Shortest Path First (OSPF)
The dominant **link-state** interior gateway protocol, and an **open standard** — which is the main reason it is deployed far more widely than EIGRP.

**How link-state works:** each router floods **LSAs** (link-state advertisements) describing its own links. Every router assembles these into an identical **link-state database** — a complete map of the topology — then independently runs **Dijkstra's shortest path first** algorithm against it to compute its own best paths.

**The consequence:** no router trusts a neighbour's summary. Each has the full picture and calculates its own answer, which is why link-state protocols do not suffer the count-to-infinity problems that distance-vector designs need split horizon and hold-down timers to contain.

**Its metric is cost**, derived from **bandwidth** — so a faster link is preferred over a shorter one measured in hops.

**Areas** are OSPF's scaling mechanism. A large network is divided into areas, all connecting to **area 0** (the backbone). LSA flooding is contained within an area and only summary information crosses between them — limiting database size, CPU cost, and the blast radius of a topology change. This is route summarization applied inside a routing protocol.

**Administrative distance: 110.** Uses multicast **224.0.0.5** (all OSPF routers) and **224.0.0.6** (designated routers) rather than broadcast, so non-participating devices ignore it at the NIC.

**Tradeoffs:** more CPU and memory than distance-vector protocols, since every router holds the full topology and runs SPF. Design matters — a poorly planned area structure scales badly.

**Areas are administratively defined**, and analogous to broadcast domains in *purpose* but not in scope: a broadcast domain contains **data-plane** flooding within one subnet, while an area contains **control-plane** LSA flooding across many subnets. Same principle — stop local churn becoming global churn — applied at different layers.

## Route selection

When multiple routes could reach a destination, a router chooses in a strict order. **All three criteria are evaluated in sequence, and each is only reached if the previous one ties.**

### Prefix length
**Checked first, and decisive.** The **most specific** matching route wins — the one with the longest prefix — regardless of administrative distance or metric.

A route to `10.1.1.0/24` beats `10.1.0.0/16`, which beats `0.0.0.0/0`, for a packet destined to `10.1.1.5`. Specificity is never overridden by the tiebreakers below; it is not compared against them.

**Why:** a more specific route represents more precise knowledge of where a destination actually is. A default route means "I don't know, try this way."

**A common misconception:** that a static route always wins over a dynamic one. It does not — a static `0.0.0.0/0` loses to an OSPF-learned `/24`, because prefix length is evaluated before administrative distance ever matters.

### Administrative distance
**Checked second — only when two routes have the same prefix length.** AD ranks how much a router trusts each *source* of routing information. **Lower is more trusted.**

| Source | AD |
|---|---|
| Directly connected | **0** |
| **Static** | **1** |
| EIGRP internal | 90 |
| **OSPF** | **110** |
| IS-IS | 115 |
| **RIP** | **120** |
| EIGRP external | 170 |
| Unknown / unusable | 255 |

**Why it exists:** if a router learns the same prefix from both OSPF and RIP, their metrics are not comparable — OSPF cost and RIP hop count measure different things. AD resolves it by trusting the protocol, not the number.

**AD 255 means the route is never installed.**

### Metric
**Checked last — only when prefix length and AD both tie**, meaning two routes from the *same* protocol. The metric is protocol-specific:

| Protocol | Metric |
|---|---|
| RIP | Hop count |
| OSPF | Cost (from bandwidth) |
| EIGRP | Composite (bandwidth + delay) |
| BGP | AS path length and policy |

> **The order in one line:** longest prefix wins outright → then lowest administrative distance → then lowest metric.

**AD is locally significant** — never advertised to neighbours, and configurable per protocol or per route. Giving a static route a *higher* AD than the dynamic protocol creates a **floating static route**: inactive while the primary exists, installed automatically if it disappears. The values above are Cisco's; other vendors use different defaults.

## Address translation

### Network address translation (NAT)
Rewriting IP addresses in packet headers as traffic crosses a boundary, allowing private internal addresses to reach the public internet.

**The three types:**

| Type | Mapping | Use |
|---|---|---|
| **Static NAT** | One private ↔ one public, permanent | Publishing an internal server at a fixed public address |
| **Dynamic NAT** | Private addresses drawn from a **pool** of public ones, first come first served | Rare; still needs one public address per concurrent host |
| **PAT / NAT overload** | **Many private → one public**, distinguished by port | Effectively all consumer and most business internet access |

**How the translation table works:** the router records each outbound flow — internal address and port, translated address and port, destination — and reverses the rewrite for returning traffic. **Entries are created only by outbound traffic**, which is why unsolicited inbound packets have no matching entry and are discarded.

**That discard is an artifact of addressing, not a security policy.** NAT is not a firewall — the point already made in Objective 1.2, and the reason your RouterOS setup needs an explicit default-deny inbound rule in addition to NAT.

**What NAT breaks:** protocols that embed IP addresses inside their payload rather than only in headers. SIP, FTP in active mode, and IPsec AH all suffer, which is why SIP ALGs, passive FTP, and NAT-Traversal exist.

### Port address translation (PAT)
NAT's many-to-one form — also called **NAT overload**. An entire private network shares **one public address**, with each conversation distinguished by a unique **source port**.

**How it works:** the router rewrites both the source address *and* the source port, recording the mapping. Two hosts both using source port 50000 receive different translated ports, so return traffic is unambiguous.

```
10.0.0.11:50000  →  203.0.113.5:41022
10.0.0.12:50000  →  203.0.113.5:41023
```

**Its capacity:** roughly 64,000 ports per public address, though practical limits are lower. This is what allows one residential IP to serve dozens of devices and hundreds of simultaneous connections.

**PAT vs. static NAT — the tested distinction:**

| | Static NAT | PAT |
|---|---|---|
| Mapping | **One-to-one** | **Many-to-one** |
| Public addresses needed | One per host | **One total** |
| Inbound reachable | **Yes** — fixed mapping | No, without a port forward |
| Purpose | Publishing a server | **Conserving addresses** |

**Port forwarding** is the exception that lets inbound traffic through PAT: a manually configured static mapping of one external port to one internal host and port. It is what a Cloudflare Tunnel avoids needing.

**Port forwarding risk:** the mapping is permanent and **unauthenticated at the network layer** — anyone can reach the service, and all protection must come from the application. Exposed ports are indexed by Shodan/Censys within hours, and mass exploitation typically follows disclosure the same day. **Never forward management protocols** (RDP 3389, SMB 445, databases, admin panels); RDP exposure is the leading ransomware initial-access vector. The most common real-world failure is a **forgotten rule** left pointing at an IP later reassigned to a different host. Safer options, in order: outbound tunnel → VPN → authenticated reverse proxy → forward with a source-IP allowlist.

### First Hop Redundancy Protocol (FHRP)
A family of protocols providing a **redundant default gateway**, so hosts do not lose connectivity when the router they point at fails.

**The problem:** every host has one default gateway address. If that router dies, every host on the subnet is isolated — even with a second router physically present — because hosts have no mechanism to notice or switch.

**How it works:** two or more routers share a **virtual IP** and virtual MAC address. Hosts use the virtual IP as their gateway and never know how many physical routers exist. One router is **active**, forwarding traffic; the others stand by, monitoring it with hello messages. If the active router stops responding, a standby assumes the virtual addresses and continues forwarding — **transparently to hosts, which see no change at all.**

**The implementations:**

| Protocol | Origin | Note |
|---|---|---|
| **HSRP** | Cisco proprietary | Active/standby |
| **VRRP** | **Open standard** | Master/backup; the multi-vendor choice |
| **GLBP** | Cisco proprietary | Adds **load balancing** across gateways, not just failover |

**HSRP and VRRP are active/passive** — the standby forwards nothing until failover. **GLBP is active/active**, distributing hosts across multiple gateways so both links carry traffic.

**Where it belongs:** the distribution layer, providing gateway redundancy for the access switches beneath it.

### Virtual IP (VIP)
An IP address **not bound to a single physical interface** — it is owned by whichever device currently holds a role, and can move between devices without clients noticing.

**Its three common uses:**

| Use | Purpose |
|---|---|
| **FHRP gateway** | The shared address hosts point at; moves to the standby router on failure |
| **Load balancer front end** | Clients connect to one address; the balancer distributes to a backend pool |
| **Cluster address** | A service address that follows the active node in an HA pair |

**The property they share is indirection.** Clients are given a stable address that hides how many devices sit behind it and which one is currently responsible. That decoupling is what allows failover and scaling to happen without touching client configuration.

**Why that matters:** without a VIP, redundancy requires clients to know about it — retry lists, DNS changes, manual reconfiguration. With one, the client's view never changes, and the failure is handled entirely on the infrastructure side.

### Subinterfaces
**Logical divisions of one physical interface**, each with its own IP address, VLAN tag, and configuration. Written as `Gi0/0.10`, `Gi0/0.20` — the parent interface, a dot, and a subinterface number conventionally matching the VLAN ID.

**Why they exist:** a router needs one interface per network it routes between. Without subinterfaces, routing between eight VLANs would need eight physical ports. Subinterfaces let a single trunked link carry all of them, with each subinterface acting as the default gateway for one VLAN.

**This is "router on a stick":**

- The **switch port** facing the router is a **trunk** (Layer 2, carries all VLANs tagged)
- The **router interface** is divided into **subinterfaces** (Layer 3, one per VLAN, each with an IP)
- Inter-VLAN traffic travels **up the trunk, gets routed between subinterfaces, and comes back down**

**Its limitation is that single link.** All inter-VLAN traffic traverses one cable in both directions, making it a bandwidth bottleneck and a single point of failure — which is why **Layer 3 switches with SVIs** replaced it in most designs, routing between VLANs in hardware without leaving the switch.

**Where subinterfaces remain standard:** routers connecting to a trunked switch, WAN links carrying multiple logical circuits, and any device with limited physical ports.
