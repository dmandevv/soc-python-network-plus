1. Identify the problem
- gather information
- duplicate the issue to see if you really found the problem (test in sandbox)
- questions users (what are they experiencing and seeing)
- identify symptoms
- ask yourself, What has changed in the last day or since a config change.
- break down into smaller steps

2. Establish a theory
- start with the obvious (cable unplugged)
- examine problem from the top to bottom of OSI Model (or start at Layer 3/4 if it's a Network problem)

3. Test the theory
- Didn't work? Reestablish the theory!

4. Establish a Plan of action
- minimum impact to business
- some issues can't be resolved during production hours
- have backup plans (check if their is a rollback that can be deployed)

5. Implement the Plan
- do during change window

6. Verify full system functionality
- test everything to ensure fix actuallty worked
- implement preventative measures

7. Document findings
- lessons learned
- audit paper trail
