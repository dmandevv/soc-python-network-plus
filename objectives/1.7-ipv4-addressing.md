# 1.7 — Given a scenario, use appropriate IPv4 network addressing

## Public vs. private

**Public addresses** are globally unique, allocated through the IANA → regional registry → ISP hierarchy, and routable across the internet. **Private addresses** are reserved ranges that anyone may use internally, are **not routable on the public internet**, and are deliberately duplicated across millions of networks.

**Why the split exists:** IPv4's 4.3 billion addresses could never cover every device. Private addressing lets an entire organization sit behind one public address, with **NAT** translating between the two worlds at the boundary.

**How routers enforce it:** internet routers are configured to drop packets addressed to private ranges. This is why a private address collision between two networks is harmless — the traffic never leaves its own network, so duplication across millions of homes causes no conflict.

**The consequence:** a device with only a private address cannot be reached from the internet unless something deliberately bridges the gap — NAT with port forwarding, a VPN, or an outbound-initiated tunnel. That property is a side effect of addressing, **not a firewall**, but it is the reason unsolicited inbound traffic does not reach hosts behind NAT.

### Automatic Private IP Addressing (APIPA)
The **169.254.0.0/16** range a host assigns itself when it requests a DHCP address and **gets no reply**. Also called a **link-local** address.

**What it provides:** communication with other APIPA hosts on the same physical segment — and nothing else. No default gateway, no DNS, no routing off the local link.

**Why it matters most as a diagnostic:** seeing a 169.254.x.x address is a definitive symptom, not a configuration. It means **the DHCP request failed** — the server is down, the scope is exhausted, a relay/IP helper is missing on a remote subnet, a VLAN is misassigned, or the cable/link is faulty.

**The troubleshooting value is that it narrows the fault immediately.** The host's network stack is working (it tried, and self-assigned), so the problem is between the host and the DHCP server rather than on the host itself.

### RFC 1918
The standard reserving three IPv4 ranges for **private use** — the addresses everyone uses internally and no router forwards across the internet.

| Range | CIDR | Addresses | Class origin |
|---|---|---|---|
| **10.0.0.0 – 10.255.255.255** | **10.0.0.0/8** | ~16.7 million | One Class A block |
| **172.16.0.0 – 172.31.255.255** | **172.16.0.0/12** | ~1 million | 16 Class B blocks |
| **192.168.0.0 – 192.168.255.255** | **192.168.0.0/16** | 65,536 | 256 Class C blocks |

**The 172.16 range is the one people get wrong.** It is **172.16 through 172.31** — not all of 172.x. The `/12` prefix covers 16 blocks, so `172.15.x.x` and `172.32.x.x` are **public** addresses belonging to someone else.

**Where each tends to be used:** 10.0.0.0/8 in large enterprises and cloud VPCs (room to subnet extensively), 192.168.0.0/16 in homes and small offices, 172.16.0.0/12 in mid-sized networks and by Docker for its default bridge.

**Not RFC 1918, but also non-routable:** 169.254.0.0/16 (APIPA), 127.0.0.0/8 (loopback), and 100.64.0.0/10 (**CGNAT**, RFC 6598 — used by ISPs between customers and their own NAT).

### Loopback / localhost
The **127.0.0.0/8** range, addressing **the host itself**. Traffic sent here never reaches a network interface — the IP stack loops it straight back internally. **127.0.0.1** is the conventional address, and **localhost** is its hostname (resolved via the hosts file, not DNS).

**Note the size:** an entire `/8` — 16.7 million addresses — is reserved for this, of which essentially only one is used. A legacy of classful allocation.

**What it is used for:**
- **Testing that the local IP stack works** — `ping 127.0.0.1` succeeding proves TCP/IP is functional even with the cable unplugged
- **Services bound to loopback only**, reachable by local processes and unreachable from the network — the security pattern behind `-p 127.0.0.1:8000:8000`
- Local development servers

**The diagnostic sequence it supports:** ping loopback (is the stack alive?) → ping own IP (is the interface configured?) → ping gateway (is the local network reachable?) → ping beyond (is routing working?). Each step isolates one layer.

**IPv6 equivalent:** `::1/128` — a single address rather than a whole block.

### Subnetting
Dividing one network into smaller networks by **borrowing bits from the host portion** and reassigning them to the network portion. Every borrowed bit doubles the subnet count and halves the hosts per subnet.

**Why do it:** to contain broadcast domains (a flat network floods every broadcast to every host), to enforce security boundaries between segments, to allocate addresses efficiently, and to keep routing tables manageable.

**The two formulas:**

| Formula | Gives |
|---|---|
| **2ⁿ** where *n* = bits borrowed | Number of subnets |
| **2ʰ − 2** where *h* = host bits remaining | Usable hosts per subnet |

The **−2** removes the **network address** (all host bits 0) and the **broadcast address** (all host bits 1) — neither can be assigned to a device.

**The block size method** — the fastest way to answer subnetting questions by hand:

1. **Block size = 256 − the interesting octet's mask value.** For /26 the mask is 255.255.255.**192**, so the block size is 256 − 192 = **64**.
2. **Subnet boundaries are multiples of the block size**: 0, 64, 128, 192.
3. **Find which block the address falls into** — that boundary is the network address.
4. **Broadcast = next boundary − 1.** First host = network + 1. Last host = broadcast − 1.

**Worked example — 192.168.1.100/26:**
- Mask 255.255.255.192 → block size 64
- Boundaries: 0, 64, **128**, 192 → 100 falls between 64 and 128, so the block starts at **64**
- Network **192.168.1.64**, broadcast **192.168.1.127**
- Usable range **.65 – .126** (2⁶ − 2 = 62 hosts)

**Common prefixes worth memorizing:**

| CIDR | Mask | Block | Usable hosts |
|---|---|---|---|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | **2** (point-to-point links) |

### Variable Length Subnet Mask (VLSM)
Using **different subnet mask lengths within the same network**, sizing each subnet to what it actually needs rather than making them all identical.

**The problem it solves:** fixed-length subnetting forces every subnet to the size of the largest one. Split 192.168.1.0/24 evenly into /26s and a point-to-point WAN link consuming 2 addresses is handed a block of 62 — wasting 60, four times over.

**The method — always allocate largest first:**

1. List each subnet's host requirement
2. Sort largest to smallest
3. Assign the smallest prefix that fits each, working down
4. Continue from where the previous block ended

**Worked example — 192.168.1.0/24 for 100 hosts, 50 hosts, 25 hosts, and two WAN links:**

| Need | Prefix | Range | Usable |
|---|---|---|---|
| 100 hosts | **/25** | 192.168.1.0 – .127 | 126 |
| 50 hosts | **/26** | 192.168.1.128 – .191 | 62 |
| 25 hosts | **/27** | 192.168.1.192 – .223 | 30 |
| WAN link 1 | **/30** | 192.168.1.224 – .227 | 2 |
| WAN link 2 | **/30** | 192.168.1.228 – .231 | 2 |

Everything fits in one /24 with **.232 – .255 still free**. Fixed /25s would have run out after two subnets.

**Why largest first matters:** allocating a small subnet early can leave the remaining space fragmented, with no block large enough for a big requirement even though enough total addresses remain.

**Requirement:** VLSM needs **classless routing protocols** that carry the subnet mask in their updates — OSPF, EIGRP, BGP, RIPv2. Classful protocols (RIPv1) assume a uniform mask and cannot support it.

### Classless Inter-Domain Routing (CIDR)
The addressing scheme that **abandoned fixed address classes** in favour of an explicit prefix length — the `/24` notation. Network and host boundaries can fall anywhere, not just on octet boundaries dictated by the first octet's value.

**The problem it solved:** classful allocation offered only three sizes — Class A (16.7 M addresses), Class B (65 K), Class C (254). An organization needing 500 addresses had to take a Class B and waste 65,000, or take two Class Cs and manage them separately. This wasted address space so aggressively that IPv4 exhaustion was projected for the mid-1990s.

**CIDR notation** replaces the class with a count of network bits: `192.168.1.0/24` means the first 24 bits are network. Any prefix length is valid, so an organization needing 500 addresses takes a `/23` (510 hosts) instead of a Class B.

**Route summarization (supernetting)** is the other half. Contiguous blocks can be advertised as one aggregate route — four adjacent `/24`s become a single `/22`. That is what keeps the internet's routing tables from growing unmanageably, and it is the same mechanism the distribution layer uses to shield the core.

**CIDR vs. VLSM:** CIDR is the *notation and allocation model* that made classless addressing possible; VLSM is *using* variable prefixes inside your own network. Both depend on the mask being carried explicitly rather than inferred.

**Summarization requires blocks to be contiguous *and* aligned.** A /23 may only begin on an even third octet, a /22 on a multiple of 4, and so on — the same block-size arithmetic as subnetting. `192.168.1.0/24` + `192.168.2.0/24` are contiguous but **cannot** be summarized as a /23, because 1 is not a valid /23 boundary; the only covering summary is 192.168.0.0/22, which also claims two networks you may not own.

## IPv4 address classes

Classes are **historical** — CIDR replaced them — but the boundaries still appear on the exam and in the naming of RFC 1918 ranges.

| Class | First octet | Default mask | Purpose |
|---|---|---|---|
| **A** | **1–126** | /8 | Very large networks |
| **B** | **128–191** | /16 | Medium networks |
| **C** | **192–223** | /24 | Small networks |
| **D** | **224–239** | — | **Multicast** |
| **E** | **240–255** | — | **Reserved / experimental** |

**127 is missing on purpose** — it sits between A and B and is reserved for **loopback**.

**The D/E boundary is the tested one:** 224.0.0.0/4 is multicast (Class D); 240.0.0.0/4 is reserved (Class E). Memory hook — **D** for **D**istribution, **E** for **E**xperimental.

**How classes were identified:** by the leading bits of the first octet — 0 for A, 10 for B, 110 for C, 1110 for D, 1111 for E. A router could infer the mask from the address alone, which is exactly the assumption CIDR discarded.
