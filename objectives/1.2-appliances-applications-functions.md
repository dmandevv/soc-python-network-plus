# 1.2 — Compare and contrast networking appliances, applications, and functions

## Physical and virtual appliances

Every appliance below exists in two forms: a **physical** dedicated hardware box, or a **virtual** instance running as software on a hypervisor or in the cloud. The function is identical — what differs is cost, performance ceiling, and flexibility. Virtual appliances deploy in minutes and scale on demand; physical ones offer dedicated hardware and purpose-built processing.

### Router
A Layer 3 device that forwards **packets between different networks**, choosing the best path using its routing table and providing the default gateway that hosts use to reach anything off their local subnet. It is the boundary between broadcast domains — routers do not forward broadcasts.

### Switch
A Layer 2 device that forwards **frames within a single network** by learning source MAC addresses into a MAC address (CAM) table and sending each frame only out the port leading to its destination. Every switch port is its own collision domain, and every VLAN its own broadcast domain.

### Firewall
A security appliance that **permits or denies traffic against a rule set**, enforcing the boundary between trusted and untrusted networks. A stateful firewall tracks active connections so return traffic is allowed automatically, while a stateless one evaluates each packet in isolation against its ACL.

### Intrusion Detection System (IDS) / Intrusion Prevention System (IPS)
Both inspect traffic for attack signatures or anomalous behavior; the difference is placement and authority. An **IDS** sits **out-of-band** (fed by a mirror/SPAN port or tap) and can only alert after the fact, while an **IPS** sits **inline** in the traffic path and can actively drop malicious traffic before it arrives.

### Load balancer
Distributes incoming client requests across a pool of backend servers, providing both **scalability** (more servers absorb more load) and **high availability** (health checks pull failed servers out of rotation automatically). Clients connect to a single **virtual IP (VIP)** and never know how many servers sit behind it.

### Proxy
An intermediary that makes requests on another party's behalf, so the two ends never talk directly. A **forward proxy** sits in front of *clients* (content filtering, caching, hiding internal users), while a **reverse proxy** sits in front of *servers* (TLS termination, caching, shielding backend systems from direct exposure).

### Network-attached storage (NAS)
A **file-level** storage appliance that attaches to the existing Ethernet network and shares folders to many clients over file protocols such as SMB or NFS. It is simple and inexpensive to deploy because it uses the network you already have, but shares that network's bandwidth with everything else.

### Storage area network (SAN)
A **block-level** storage network, usually on its own dedicated high-speed fabric (Fibre Channel or iSCSI), that presents raw storage volumes to servers as if they were locally attached disks. The server formats and owns the filesystem itself, which gives the low latency and consistent throughput that databases and virtualization need.

**NAS vs. SAN:** NAS serves *files* over the existing network to many clients; SAN serves *blocks* over a dedicated fabric to servers.

### Wireless — Access point (AP)
A Layer 2 device that bridges wireless clients onto the wired network, converting between 802.11 radio frames and 802.3 Ethernet frames. An AP is **not** a router — it extends an existing network rather than creating a new one, and it is a shared half-duplex medium, so all clients on a radio contend for the same airtime.

### Wireless — Controller
A **WLC (Wireless LAN Controller)** centrally manages a fleet of lightweight APs — pushing configuration, coordinating channel and power assignments, and enabling seamless roaming between APs. It turns dozens of individually-configured devices into one system administered from a single place.

## Applications

### Content delivery network (CDN)
A geographically distributed network of **edge servers** that cache copies of content close to users, so requests are served from a nearby location instead of travelling to the origin server. This cuts latency, reduces load on the origin, and absorbs traffic spikes and DDoS attacks across the distributed footprint.

## Functions

### Virtual private network (VPN)
Creates an encrypted **tunnel** across an untrusted network, so traffic traverses the public internet with the privacy and reachability of a private link. **Site-to-site** VPNs join two networks permanently; **client-to-site** (remote access) VPNs connect an individual device into a network.

**Note:** "VPN" names the solution category, not encryption itself — the security comes from the underlying protocol (IPsec, TLS). GRE, L2TP alone, MPLS VPNs, and IPsec in AH-only mode all tunnel *without* encrypting.

### Quality of service (QoS)
Prioritizes traffic so latency-sensitive applications get served first when a link is congested. It cannot create bandwidth — it only decides who suffers when there isn't enough, which is why it matters for voice and video but does nothing on an uncongested link.

### Time to live (TTL)
A counter in the IP header, decremented by 1 at every router hop, that causes a packet to be discarded when it reaches zero — guaranteeing that looping packets eventually die instead of circulating forever. It is also the mechanism `traceroute` exploits to map a path, and the term is reused in DNS to mean how long a cached record stays valid.
