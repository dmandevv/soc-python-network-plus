# 1.1 — Explain concepts related to the OSI reference model

The Open Systems Interconnection (OSI) reference model is a seven-layer conceptual framework describing how data moves from an application on one device, down through the network, and back up to an application on another. Each layer serves the one above it and relies on the one below.

## Layers

### Layer 1 — Physical
The raw transmission of bits as electrical signals, light pulses, or radio waves across a physical medium — cables, connectors, radio frequencies, and the voltage/timing rules that define a 1 versus a 0. It has no concept of addressing or meaning; it only moves signals.

**Devices/examples:** cables (copper, fiber), hubs, repeaters, transceivers, connectors (RJ45, LC), radio waves.
**Troubleshooting:** bad cable, wrong cable type, attenuation, crosstalk, interference, no link light.

### Layer 2 — Data Link
Packages bits into **frames** and delivers them between devices on the *same* local network using physical **MAC (Media Access Control) addresses**. It also handles error *detection* (via the frame's CRC) and controls which device may transmit on a shared medium.

**PDU:** frame. **Addressing:** MAC address (48-bit, burned into the NIC).
**Devices/examples:** switches, bridges, network interface cards (NICs), wireless access points; 802.1Q VLAN tagging and Spanning Tree Protocol (STP) live here.
**Troubleshooting:** wrong VLAN assignment, switching loops, CRC errors, runts/giants, duplex mismatch.

### Layer 3 — Network
Moves **packets** between *different* networks using hierarchical logical **IP (Internet Protocol) addresses**, and selects the path to take — this is where routing happens. Its addresses encode location (network + host), which is what makes forwarding decisions possible at internet scale.

**PDU:** packet. **Addressing:** IP address (logical, assigned, hierarchical).
**Devices/examples:** routers, Layer 3 switches; IPv4/IPv6, ICMP, and the routing protocols (OSPF, BGP, EIGRP) operate here, as do TTL and fragmentation.
**Troubleshooting:** wrong IP address or subnet mask, incorrect default gateway, routing loops, missing routes.

### Layer 4 — Transport
Provides end-to-end communication between *applications* rather than between devices, using **port numbers** to identify which service traffic belongs to. It also decides the delivery guarantee: TCP adds reliability, ordering, and flow control, while UDP offers none of it in exchange for lower overhead.

**PDU:** segment (TCP) / datagram (UDP). **Addressing:** port number (0–65535).
**Devices/examples:** TCP, UDP; firewalls and load balancers that filter or distribute by port operate here.
**Troubleshooting:** blocked port, service listening on the wrong port, exhausted connection table.

### Layer 5 — Session
Establishes, maintains, and terminates the ongoing **dialogue** between two applications — including dialog control (who transmits when) and checkpointing so an interrupted long transfer can resume rather than restart. A session sits above a Layer 4 connection and may outlive or span several of them.

**Devices/examples:** SIP (Session Initiation Protocol) for setting up and tearing down voice/video calls, RPC (Remote Procedure Call), NetBIOS.
**Note:** the TCP/IP model collapses Layers 5–7 into one Application layer, so few real protocols map cleanly here — the layer is mostly a conceptual distinction on this exam.
**Troubleshooting:** session timeouts, calls that connect but drop, re-authentication loops.

### Layer 6 — Presentation
Translates data into a form the receiving application can understand — character encoding, data formatting, **encryption/decryption**, and **compression**. It is the "translator" layer, ensuring a message written on one system is intelligible on another regardless of internal representation.

**Devices/examples:** TLS/SSL encryption, ASCII/Unicode encoding, JPEG/PNG/GIF, MPEG, ZIP/gzip compression.
**Troubleshooting:** certificate errors, cipher-suite mismatch, garbled or unreadable characters, files that won't open.

### Layer 7 — Application
The layer closest to the user, providing the **network services applications use** — not the applications themselves. A web browser is not Layer 7; the HTTP it speaks is.

**Devices/examples:** HTTP/HTTPS, DNS, DHCP, FTP, SMTP, SSH, SNMP, LDAP; next-generation firewalls and proxies that inspect application content operate here.
**Troubleshooting:** service misconfiguration, DNS resolution failures, expired credentials, application-specific errors returned over a working connection.

## Quick reference

| Layer | Name | PDU | Addressing | Key examples |
|---|---|---|---|---|
| 7 | Application | Data | — | HTTP, DNS, DHCP, SMTP, FTP |
| 6 | Presentation | Data | — | TLS encryption, ASCII/Unicode, JPEG, compression |
| 5 | Session | Data | — | SIP, RPC, NetBIOS |
| 4 | Transport | Segment / Datagram | Port number | TCP, UDP |
| 3 | Network | Packet | IP address | IP, ICMP, OSPF, BGP, routers |
| 2 | Data Link | Frame | MAC address | Ethernet, 802.1Q, STP, switches |
| 1 | Physical | Bits | — | Cables, fiber, radio, hubs, transceivers |

**Mnemonic (Layer 7 → 1):** *All People Seem To Need Data Processing.*
**Mnemonic (Layer 1 → 7):** *Please Do Not Throw Sausage Pizza Away.*
